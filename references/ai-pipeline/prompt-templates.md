# 提示词模板库 — 工具无关

> 不绑定任何特定 AI 工具。复制 → 粘贴到任何 LLM → 获得结构化输出。

## 设计原则：「角色-目标-条件」框架

每个有效的提示词都有三个要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| **角色** | AI 充当什么角色 | 「你是信息结构化专家」 |
| **目标** | 要输出什么 | 「以 Markdown 格式输出思维导图」 |
| **条件** | 格式、长度、风格约束 | 「层级≤4」「每节点≤15字」「只输出代码」 |

## 模板一：文本 → 思维导图 Markdown

```
请根据以下内容，按照思维导图的层级结构进行整理，以 Markdown 格式输出。

要求：
- 使用 # 作为中心主题，## 作为主要分支，### 作为子分支，- 作为叶子节点
- 层级不超过 4 层，保持结构清晰
- 每个节点的文字简洁明了，不超过 20 字
- 只输出 Markdown 代码，不要任何额外解释

内容如下：

[这里粘贴你的文本]
```

**适用场景**：已有文本内容，需要梳理成导图。

## 模板二：主题 → 扩展大纲

```
请为主题「[主题]」生成一份结构化的思维导图大纲，以 Markdown 格式输出。

要求：
- 使用 # 作为中心主题，## 作为主要分支，### 作为子分支，- 作为细节节点
- 覆盖该主题的所有关键方面，做到全面且有逻辑层次
- 层级不超过 4 层
- 每个节点的文字简洁明了
- 只输出 Markdown 代码，不要任何额外解释
```

**适用场景**：只有一个主题/想法，需要 AI 帮忙扩展。

## 模板三：图片 → 导图重建

```
请根据这张图片中的思维导图，识别其结构和文字内容，整理成 Markdown 格式输出。

要求：
- 保持原始层级结构，使用 # ## ### - 表示
- 文字内容与图片保持一致
- 如果图片中有模糊不清的文字，用 [?] 标注
- 只输出 Markdown 代码
```

**适用场景**：手头有思维导图图片，想数字化编辑。

## 模板四：流程描述 → Mermaid 流程图

```
请将以下流程/逻辑整理成 Mermaid 格式的流程图代码。

要求：
- 使用 graph TD 定义从上到下的方向
- 起止节点用圆角 ( )，处理步骤用方括号 [ ]，决策用菱形 { }
- 节点文字简洁，不超过 15 字
- 只输出 Mermaid 代码块，不要任何额外解释

流程描述：

[这里描述你的流程]
```

**适用场景**：需要画流程图，不想手动画。

## 模板五：结构化分析（SWOT/鱼骨图等）

```
请对「[分析对象]」进行 [分析方法] 分析，以 Markdown 格式输出结构化结果。

要求：
- [描述你需要的结构，如：四象限 / 6大类原因 / 决策树形]
- 每个要点简洁，不超过 25 字
- 只输出 Markdown 代码
```

**示例**：
```
请对「我们的新产品进入饱和市场」进行 SWOT 分析，以 Markdown 格式输出。

要求：
- 分为优势(S)、劣势(W)、机会(O)、威胁(T) 四个象限
- 每个象限 3-5 个要点
- 每个要点不超过 25 字
- 只输出 Markdown 代码
```

## 通用优化技巧

| 问题 | 在提示词末尾加上 |
|------|-----------------|
| AI 输出太多废话 | 「只输出 Markdown 代码，不要任何额外解释」 |
| 层级太深 | 「层级不超过 3 层」 |
| 节点文字太长 | 「每个节点不超过 10 字」 |
| 结构不符合预期 | 「请按照 [具体结构] 组织」 并举例 |
| 内容太泛 | 「请给出具体、可执行的建议，避免空泛」 |

## 多轮对话策略

不需要一次完美。可以分多轮：

1. **第一轮**：给出内容 + 「请整理成 Markdown 思维导图」
2. **第二轮**：「第三层太简略，请展开第 2、4 条分支」
3. **第三轮**：「请将 ## 职业发展 下面的内容重新整理，按时间线排列」

迭代式调整比一次写好提示词更高效。
