# 文本 → 思维导图 完整流程

> 把任何文本变成 XMind 可编辑的思维导图，3 分钟完成。

## 流程总览

```
你的文本 → AI 生成 Markdown 代码 → 保存 .md 文件(UTF-8) → XMind 导入 → 可编辑导图
```

## 第一步：准备素材

收集你要整理的内容，可以是：
- 一篇文章 / 一本书的章节
- 会议记录 / 对话 transcript
- 项目需求文档
- 任何你想「结构化」的文本

## 第二步：使用 AI 生成 Markdown

打开任意 AI 工具（DeepSeek / KIMI / Claude / ChatGPT / 豆包...都可以），使用以下提示词：

```
请根据以下内容，按照思维导图的层级结构进行整理，以 Markdown 格式输出。

要求：
- 使用 # 作为中心主题，## 作为主要分支，### 作为子分支，- 作为叶子节点
- 层级不超过 4 层，保持结构清晰
- 每个节点的文字简洁明了，不超过 20 字
- 只输出 Markdown 代码，不要任何额外解释

内容如下：

[这里粘贴你的文本]
```

**提示词设计原理**（「角色-目标-条件」框架）：
- **角色隐含**：让 AI 充当信息结构化者
- **目标明确**：输出 Markdown 格式的思维导图
- **条件约束**：层级 ≤4、节点 ≤20 字、只要代码

## 第三步：保存为 .md 文件

> ⚠️ **这一步最容易出错，请严格按步骤操作！**

1. 在 AI 界面中**点击「复制」按钮**（不要用 Ctrl+A / Ctrl+C，避免格式丢失）
2. 打开记事本（Windows）或文本编辑（Mac），粘贴内容
3. 点击 **另存为** → 保存类型选 **「所有文件」**
4. 文件名：`主题名称.md`（后缀必须是 `.md`）
5. 编码：**必须选 UTF-8**（否则中文乱码！）

**检查**：在文件资源管理器中确认文件名是 `xxx.md`，不是 `xxx.md.txt`。

## 第四步：导入 XMind

1. 打开 XMind
2. 菜单 → **文件 → 导入 → Markdown**
3. 选择上一步保存的 `.md` 文件
4. 思维导图自动生成！

## 第五步：微调和美化

- 切换布局：右侧面板 → 选择「思维导图」「逻辑图」「组织结构图」等
- 换主题配色：右侧面板 → 主题
- 添加图标标记优先级
- 调整节点位置（拖拽即可）
- 添加联系线（`Ctrl+L`）标注关联

详细美化操作参考 [XMind指南](../software/xmind-guide.md)。

## 文档类型适配

> 来自 [mindmap-generator](https://github.com/Dicklesworthstone/mindmap-generator)：不同类型文档需要不同的结构化策略。

在提示词中追加文档类型声明，让 AI 采用最佳提取策略：

| 文档类型 | 提示词追加 | AI 会怎么处理 |
|---------|-----------|-------------|
| 法律文书 | 「这是一份法律文件」 | 保留条款编号、精确引用、适用范围 |
| 技术文档 | 「这是一份技术文档」 | 保留参数值、API名称、版本号、配置项 |
| 学术论文 | 「这是一篇学术论文」 | 提取论点-论据-引用链、方法论名称 |
| 商业报告 | 「这是一份商业报告」 | 保留财务数字、百分比、时间节点、责任人 |
| 会议记录 | 「这是一份会议记录」 | 按议题分组、标注发言人和行动项 |
| 叙事文本 | 「这是一篇叙事文章」 | 保留事件顺序、人物关系、因果链 |

### 完整示例（技术文档）

```
你是一位信息结构化专家。这是一份技术文档。

请根据以下内容，按照思维导图的层级结构进行整理，以 Markdown 格式输出。

要求：
- 保留所有参数名、API端点、版本号、配置项不变
- 识别「概述→配置→API→示例→故障排查」等标准技术文档结构
- 代码块和配置示例标注为叶子节点
- 只输出 Markdown 代码，不要任何额外解释

内容如下：[粘贴技术文档]
```

## 技巧

- **文本太长（>2000 字）？** 先让 AI 总结关键点，再用提示词生成导图
- **AI 输出有废话？** 在提示词中强调「只输出 Markdown 代码，不要任何额外解释」
- **层级不满意？** 导入手动调整比反复修改提示词更高效
- **想要更漂亮的导图？** 在 XMind 中修改主题，一键换色
- **不确定文档类型？** 先让 AI 回答「这是什么类型的文档？主要结构是什么？」再生成导图
