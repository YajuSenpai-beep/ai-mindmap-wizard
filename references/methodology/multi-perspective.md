# 多视角分析 — 同一内容的不同切面

> 来自 [oh-my-mermaid](https://github.com/oh-my-mermaid/oh-my-mermaid) 和 [llmapper-skill](https://github.com/jorgearango/llmapper-skill)：好内容值得用多个视角审视。

## 概述

同一个主题，从不同视角切入会得到完全不同的导图。多视角分析帮你穷尽一个主题的所有维度，避免「画完才发现漏了一大块」。

## 五个通用视角

| 视角 | 问题 | 适合场景 |
|------|------|---------|
| **结构视角** | 它由哪些部分组成？层级关系是什么？ | 系统设计、组织架构、知识体系 |
| **流程视角** | 事情怎么流转？数据怎么流动？ | 业务流程、算法、API 调用链 |
| **关系视角** | 谁依赖谁？谁影响谁？ | 系统集成、团队协作、竞争分析 |
| **时间视角** | 怎么演化的？关键节点是什么？ | 项目规划、历史分析、版本演进 |
| **对比视角** | 有什么替代方案？优劣是什么？ | 技术选型、竞品分析、方案评估 |

## 操作流程

### 1. 生成聚焦问题

在分析一个主题前，先让 AI 生成 3 个聚焦问题，帮你选择最有价值的视角：

```
提示词：
对于主题「[主题]」，请生成 3 个不同的聚焦问题，每个问题代表一个分析视角。
例如：
- 「这个系统的核心组件和它们的依赖关系是什么？」（结构视角）
- 「数据在这个系统中如何流转？」（流程视角）
- 「这个系统与其他系统的集成点在哪里？」（关系视角）
```

### 2. 选择一个视角深入

选最相关的一个视角，生成该视角的专属提示词：

```
提示词（结构视角示例）：
请从「系统结构」的角度，对「[主题]」进行思维导图式梳理。
重点关注：模块划分、层级关系、组件职责、接口定义。
输出 Markdown 格式。
```

### 3. 交叉对比

如果时间允许，用 2-3 个视角各生成一张导图，然后对比：

- 哪些节点在多个视角中都出现？（核心概念）
- 哪些节点只在某个视角中出现？（视角盲区）
- 合并多视角后，有没有出现新的洞察？

## RDF 模式：以知识图谱为源

> 来自 [llmapper-skill](https://github.com/jorgearango/llmapper-skill)：用 RDF 三元组（主语-谓语-宾语）作为中间表示，再生成可视化。

这个模式的价值在于：**编辑在 RDF 层做，可视化自动更新**。

```
我们的简化版：
  Markdown 源 → 检查并修改 Markdown → 重新导入 XMind

RDF 模式：
  内容 → RDF 三元组（知识图谱）→ Mermaid 可视化
         ↑                          ↓
         编辑在这里             自动重新生成
```

对于我们的工作流，Markdown 就是「源」。这意味着：
- 发现导图需要修改时，**改 Markdown 而非在 XMind 里拖来拖去**
- 改完 Markdown → 重新导入 XMind → 自动化更新
- 保留 Markdown 源文件，可版本控制、可 diff
