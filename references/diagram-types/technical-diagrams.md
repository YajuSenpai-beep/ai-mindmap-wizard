# 技术图表

> 系统怎么设计？数据怎么存储？——面向开发者和技术团队。

## 适用场景

- 数据库设计和实体关系建模
- 软件架构和系统设计
- 网络拓扑和服务器部署
- 电子电路设计
- 系统间交互和信息传递

## 图表类型对比

| 类型 | 用途 | 关键特征 |
|------|------|---------|
| **ER 图** | 数据库表结构和关系 | 实体（表）、属性（字段）、关系（1:1/1:N/N:M） |
| **UML 建模图** | 软件系统的各种视角建模 | 类图/用例图/时序图/活动图/状态图等 |
| **架构图** | 系统整体结构和技术栈 | 模块/组件/层/接口、技术选型标注 |
| **拓扑图** | 网络设备连接和结构 | 设备节点、连线=连接、标注IP/端口 |
| **电路图** | 电子元件和连接 | 标准电气符号、连线=导线、标注参数 |
| **时序图** | 对象间交互的时间顺序 | 竖线=对象/组件，横箭头=消息，自上而下=时间 |
| **网络图** | 计算机网络的结构和路由 | 路由器/交换机/服务器/终端节点、协议标注 |
| **系统拓扑图** | 系统部署的物理/逻辑拓扑 | 服务器集群、负载均衡、数据库主从 |

## 通用绘制流程

1. **确定范围**：画多大？整个系统还是一个模块？
2. **选择视角**：逻辑视图（功能）还是物理视图（部署）？
3. **标识核心元素**：列出所有关键实体/组件/对象
4. **标注关系**：连线 + 关系描述（调用/依赖/继承/数据流向）
5. **补充细节**：接口名称、协议、端口、IP、字段类型等
6. **添加图例**：技术图表必须有图例解释符号含义

## 各图表要点

### ER 图
- 每个实体 = 一张数据库表，标注主键和外键
- 关系标注：1:1 / 1:N / N:M
- 用乌鸦脚（Crow's Foot）标注法或 Chen 标注法
- draw.io 有完整 ER 图符号库

### UML 建模图
- 最常用的是类图（结构）和时序图（交互）
- 类图：类名 + 属性 + 方法，标注继承/实现/关联
- 时序图：从上到下 = 时间推进，横箭头 = 消息调用
- 推荐用 [[../ai-pipeline/mermaid-flowchart]] 生成时序图 Mermaid 代码

### 架构图 / 拓扑图 / 系统拓扑图
- 从高层到低层：先画整体架构，再展开子系统
- 用颜色区分不同的层/域（前端/后端/数据层）
- 标注技术选型：框架名、数据库类型、中间件
- 拓扑图要标注关键网络信息（IP 段、端口号）

### 电路图
- 使用标准电气符号，不要自创
- 标注元件编号和参数值
- 走线尽量少交叉，交叉处标注是否连接

### 时序图
- 与 UML 时序图类似但更通用
- 核心：谁在什么时间点做了什么操作
- 适合描述 API 调用链、消息传递过程

## 自查

1. 图例是否完整？所有符号都有解释？
2. 关系标注是否明确？（调用/依赖/继承/数据流）
3. 技术标注是否最新？（框架版本、协议版本）
