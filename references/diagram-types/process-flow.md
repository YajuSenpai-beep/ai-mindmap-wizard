# 流程图类

> 事情怎么做？数据怎么流？——描述步骤、顺序和逻辑。

## 适用场景

- 描述业务流程/审批流程
- 设计软件逻辑/算法步骤
- 展示数据流向和系统交互
- 分析生产过程和工艺步骤
- 定义程序的控制逻辑

## 图表类型对比

| 类型 | 用途 | 关键特征 |
|------|------|---------|
| **业务流程图** | 描述业务操作的端到端流程 | 泳道（按角色分区）、活动节点、决策点 |
| **软件流程图** | 描述程序/算法的逻辑步骤 | 起止节点、处理步骤、判断分支、循环 |
| **数据流图** | 描述数据在系统中的流动和变换 | 外部实体、处理过程、数据存储、数据流 |
| **工艺流程图** | 描述生产/制造过程 | 物料流向、设备/工序节点、输入输出 |
| **系统流程图** | 描述系统间的交互和整体流程 | 系统边界、接口、数据传递 |
| **程序流程图** | 描述代码执行逻辑 | 类似软件流程图，更接近代码结构 |
| **控制流图** | 描述程序的控制转移路径 | 基本块、跳转关系、循环结构 |

## 通用绘制流程

1. **确定起点和终点**：流程从哪开始？到哪结束？
2. **列出所有步骤**：用便签/列表先罗列，再排序
3. **识别决策点**：哪里需要判断？有几个分支？
4. **画主流程**：先画「快乐路径」（一切顺利的流程）
5. **补充异常路径**：出错、超时、拒绝等情况
6. **检查完整性**：每个决策分支都有出口？没有死循环？

## 流程图节点规范

| 形状 | 含义 | 使用规则 |
|------|------|---------|
| 圆角矩形 | 开始/结束 | 一张图只有 1 个开始、1-2 个结束 |
| 矩形 | 处理步骤 | 动-宾结构：「审核订单」「发送邮件」 |
| 菱形 | 判断/决策 | 二选一问题：「是否通过？」「金额>1000？」 |
| 平行四边形 | 数据/输入输出 | 数据库读写、文件导入导出 |
| 圆形 | 连接点 | 跨页连接用 |

## 各流程图要点

### 业务流程图
- 推荐使用泳道图（按角色分横条）
- 每个活动必须有明确的执行者
- 关注「谁在什么时候做什么」

### 软件/程序流程图
- 用 [Mermaid流程图](../ai-pipeline/mermaid-flowchart.md) 生成 Mermaid 代码 → 导入 draw.io
- 保持单一入口、单一出口的结构化原则
- 循环要标注循环条件和出口

### 数据流图
- 外部实体用方框，处理过程用圆/椭圆，数据存储用双线
- 数据流方向用箭头标注
- 不要出现「数据从存储直接流向另一个存储」

## 自查

1. 每个决策菱形都有「是」和「否」两个出口？
2. 所有路径最终都能到达「结束」节点？
3. 节点文字是否简洁（≤15 字）且用动-宾结构？
